# Progress and learnings — GATE → SSD CZT waveform pipeline

This document summarizes the work done on this branch (`savory-evening`) so the
project can be picked back up later or handed to a different agent. It covers
what was built, what we learned about SolidStateDetectors.jl behaviour, key
configuration choices, and the most important open questions.

## Pipeline at a glance

GATE Monte-Carlo photon interactions → SolidStateDetectors.jl simulation →
volts-calibrated waveforms and analysis plots.

| Stage | Script | Output |
|---|---|---|
| Read GATE `blurred` RNTuple, map lab → SSD frame, photopeak select | `scripts/load_gate_hits.py` | `output/sweep/gate_events_<tag>.csv` |
| Generate the full 39-anode / steering / 8-cathode geometry | `scripts/gen_full_geometry.jl` | `geometries/czt_cross_strip_full.yaml` |
| Solve E-potential + all 48 weighting potentials once and cache | `scripts/build_wp_cache.jl` | `$SSD_CACHE` (default `output/sweep/sim_cache.jls`) |
| Single-file event-driven sim (a few events, subset of WPs) | `scripts/simulate_gate_events.jl` | `output/gate_waveforms_*.json` |
| Multi-file sweep (45 real events across 9 slit positions) | `scripts/sweep_pipeline.jl` | `output/sweep/gate_waveforms_x*mm.json` |
| Single-event "ideal-position" counterpart (9 depths) | `scripts/ideal_sweep.jl` | `output/sweep_ideal/gate_waveforms_*.json` |
| Lateral charge-sharing scan past `anode_20` | `scripts/lateral_sweep.jl` | `output/lateral/lateral_sweep.json` |
| Plotting (per-event, sweep, aligned-volts, ideal-vs-fuzzy, lateral, …) | `scripts/plot_*.py`, `scripts/plot_*.jl` | `output/**/*.png` |
| CI driver on self-hosted runner | `.github/workflows/sweep.yml` | uploaded artifact |

`docs/PROGRESS.md` (this file), `output/`, `*.jls`, `*.jld2`, `.claude/` are
gitignored; only code is committed.

## Coordinate frame (the most important convention)

GATE records interactions in a **lab** frame. The collimator sweep shifts the
crystal in lab-X, so the same lab-X = 0 beam illuminates a **different depth
inside the crystal** at each slit position.

```
ssd_x = gate_Z - 120      # 40 mm anode-segmentation axis
ssd_y = gate_Y            # 40 mm cathode-segmentation axis
ssd_z = gate_X - x_off    # 5 mm drift axis (anode +2.5, cathode -2.5)
```

`x_off` is the slit label parsed from the filename (`blurred_merged_x+2.0mm.root`
→ `+2.0`). With this offset, the sweep produces a clean depth scan of mean
`ssd_z` from ≈ +1.6 mm (slit −2, anode side) to ≈ −1.8 mm (slit +2, cathode
side). The wrong (no-offset) version made the sweep look like it barely moved
depth at all — a near-disaster avoided by sanity-checking per-file `gate_X`
ranges before trusting the transform.

`scripts/load_gate_hits.py` enforces this and additionally drops events that
sit within `EDGE_MARGIN = 0.2 mm` of any face so the charge cloud fits inside
the semiconductor.

## Detector geometry

Generated by `scripts/gen_full_geometry.jl` into
`geometries/czt_cross_strip_full.yaml`. 48 contiguous contact IDs:

* **anodes 1..39** at x = −19 mm … +19 mm, 1 mm pitch, 100 µm wide, z = +2.5 mm,
  0 V (`anode_id_for_x(x) = round(x) + 20`).
* **steering (id 40)** — 40 strips at half-integer x, 400 µm wide, −80 V.
* **cathodes 41..48** at y centres ±2.5, ±7.5, ±12.5, ±17.5 mm; 4.9 mm wide;
  z = −2.5 mm; −600 V (`cathode_id_for_y(2.5) = 45`).

Crystal is 40 × 40 × 5 mm CdZnTe, drift along z, `IsotropicChargeDriftModel`
with electron lifetime 10 µs / hole 1 µs.

## Weighting-potential cache

Solving all 48 WPs at refinement `[0.2, 0.1, 0.05]` takes ~260 s, dominates a
cold run, and is geometry-only. We cache the solved `Simulation` via Julia's
`Serialization` (NOT JLD2 — the steering electrode is a 40-deep nested
`CSGUnion` parametric type and JLD2 fails to round-trip it with `EOFError`).
Cache file is ~534 MB; `deserialize` takes ~0.3 s.

* Build it once: `julia --project=. -t8 scripts/build_wp_cache.jl`
* Reuse: every other script (`sweep_pipeline.jl`, `ideal_sweep.jl`,
  `lateral_sweep.jl`) honours `ENV["SSD_CACHE"]` and falls back to
  `output/sweep/sim_cache.jls`. The CI workflow exposes this as a repo
  variable so a shared on-cluster cache can be reused.

## Key findings (in order of how badly I got each one wrong the first time)

### 1. The "depth doesn't vary across the sweep" miss
First mapping was `ssd_z = gate_X`. Per-file `gate_X` distributions then looked
nearly identical, so the sweep appeared to be a *lateral* scan with no depth
variation. **Wrong.** Per-file min/max of `gate_X` showed the window shifts by
the full slit offset (`[-2.5, 2.5]` → `[-0.5, 4.5]` at slit +2 mm), and the
correct mapping (subtracting `x_off`) revealed a ±1.8 mm depth scan. **Lesson:
verify ingest transforms against per-condition distributions, don't assume.**

### 2. The anode-rise staircase ("3 wrong guesses before the right answer")
Stepped anode rise at the ideal point (x=0, y=2.5, z=+2.0 mm). My guesses:

| Hypothesis | Verdict |
|---|---|
| Charge-cloud carrier count discretization | Wrong — N=50/shells=2 vs N=800/shells=4 and 0.05 mm jitter all step identically. |
| Anode WP grid coarseness (the known 100 µm under-resolution) | Wrong — refining anode_20 WP from 21 → 45 z-cells near the strip changed nothing. |
| Electric-field grid coarseness | Wrong — refining E-field from 6 → 12 z-cells near the anode changed nothing. |
| **Charge-cloud spatial extent (the radius)** | **Right.** A `PointCharge` is smooth; sweeping `radius` 0.5 → 0.05 mm collapses the staircase. |

Root cause: SSD's default Gamma `radius_guess = 0.5 mm` puts the outer
`NBodyChargeCloud` shell at **1.0 mm radius** (shells at 1·r and 2·r). With the
anode gap only 0.5 mm at our test position, the shells span a huge range of
depths and arrive in discrete groups (no diffusion model in this geometry).

**Fix:** pass `radius = [0.1 mm]` (or similar physical value) to the `Event`
constructor. All production scripts now use 0.1 mm by default.

**Lesson:** when an artifact survives every grid-resolution test you can think
of, the source has to be the discrete *input*, not the discrete *interpolant*.
And read the library docstrings/source for parameter semantics before assuming
defaults are sensible.

### 3. NBodyChargeCloud parameter semantics
* `N` is **not** a number of electrons — it's the number of *macro-charge sampling
  points*. The 662 keV deposit produces ~143 k e-h pairs, distributed across
  the `N` points with `exp(-n²/2)` radial weighting.
* `number_of_shells` controls the geometric Platonic-solid shell *count*, with
  shell radii at `1·r, 2·r, ...`.
* `shell_structure` picks among Tetrahedron / Cube / Octahedron / Dodecahedron
  (default) / Icosahedron — **all roughly spherical**. There is **no built-in
  disk / cylinder / track shape**. For that you'd construct a custom point list
  and pass it to `Event(locations, energies)` directly (bypassing
  `NBodyChargeCloud`).
* The physical 662 keV photoelectron range in CdZnTe is ~0.18–0.30 mm, so
  `radius = 0.1 mm` is on the conservative end; literature-realistic clouds are
  closer to a 0.2 mm oblate ellipsoid.

### 4. Voltage calibration is one knob
The preamp is a leaky integrator with arbitrary gain `b0 = 1400` and pole at
`τ = 140 µs`. Internal "preamp output" is in a.u. To get mV: assume a
feedback capacitance (`C_f = 1 pF` by default) and scale so a full-energy
plateau equals `Q / C_f = 22.86 fC / 1 pF ≈ 22.86 mV`. The scale factor is
applied uniformly so anode plateaus ≈ 22 mV across photopeak events and
cathodes carry the depth signal. `C_FEEDBACK_PF` is a one-line knob in
`scripts/plot_sweep_aligned.py` and `scripts/plot_lateral.py` — drop in the
real preamp's feedback capacitance to get true volts.

### 5. Depth encoding survives anode-aligned cleanup
After CFD-style alignment of all average anodes at their 10% rising edge and
shifting each cathode by its anode's Δt, **the cathode amplitude alone encodes
depth**: blue (near-anode) ≈ −5 mV → red (near-cathode) ≈ −23 mV in the
sweep_average plot. Anode plateaus collapse to a narrow ~22-25 mV band — the
energy signal is depth-independent as expected for small-pixel anodes. This
is the canonical CZT readout: anode = energy, cathode/anode-ratio = depth.

### 6. Lateral charge-sharing is very tight at r = 0.1 mm
17-point scan at 0.1 mm steps from x = −0.8 to +0.8 mm, fixed y = +2.5,
z = 0 (mid-plane), past `anode_20`:

* Full ~22.8 mV plateau on the collecting anode for |x| ≤ 0.3 mm.
* Sharp transition centred on the **steering strip at x = ±0.5 mm**:
  anode_20 ≈ neighbor ≈ 9 mV at that point (50/50 split).
* Charge-sharing region is **~200 µm wide** (10–90% transition).
* Anode_18 / anode_22 (one strip further out) carry effectively zero plateau.
* Steering electrode shows a positive ~10 mV current transient at t≈0.2 µs
  as the cloud transits the grid, then settles to a small negative plateau.

Cranking the cloud to **r = 0.2 mm** (closer to the photoelectron range
literature value) **doubles** the charge-sharing width to ~500 µm, halves the
flat top to ~ ±0.1 mm, and starts re-introducing mild staircasing in the
partial-charge rise shapes. The r = 0.1 mm JSON is preserved at
`output/lateral/lateral_sweep_r0.1mm.json` for direct comparison.

## Configuration choices (current defaults)

| Parameter | Value | Where |
|---|---|---|
| Cloud radius | **0.1 mm** (production) | `sweep_pipeline.jl`, `ideal_sweep.jl`, `lateral_sweep.jl` |
| Number of cloud points | 50 | same |
| `number_of_shells` | 2 | same |
| Drift Δt | 0.1 ns | same |
| max drift steps | 50 000 (≈ 5 µs) | same |
| Preamp `b0` | 1400 | same |

| Pair-creation energy `w` | 4.64 eV | same |

| Per-file events selected | 5, random | `load_gate_hits.py --n 5 --random` |
| Cache file | `output/sweep/sim_cache.jls` (`$SSD_CACHE`) | `build_wp_cache.jl` etc. |

## How to reproduce a full pass locally

```bash
# 1. Generate event CSVs from the GATE dataset (gate_env: uproot + awkward)
for f in $GATE_DATA_DIR/blurred_merged_x*.root; do
  $GATE_ENV_PYTHON scripts/load_gate_hits.py "$f" --n 5 --random --outdir output/sweep
done

# 2. (One-time) Build the cache. ~260 s. Skip if SSD_CACHE already points at one.
JULIA_NUM_THREADS=8 julia --project=. -t8 scripts/build_wp_cache.jl

# 3. Run the three sweeps (each loads the cache in ~0.3 s)
JULIA_NUM_THREADS=8 julia --project=. -t8 scripts/sweep_pipeline.jl
JULIA_NUM_THREADS=8 julia --project=. -t8 scripts/ideal_sweep.jl
JULIA_NUM_THREADS=8 julia --project=. -t8 scripts/lateral_sweep.jl

# 4. Generate the plots
python scripts/plot_sweep.py output/sweep
python scripts/plot_sweep_aligned.py output/sweep
python scripts/plot_sweep_aligned.py output/sweep_ideal
python scripts/plot_sweep_variation.py output/sweep
python scripts/plot_ideal_vs_fuzzy.py
$GATE_ENV_PYTHON scripts/plot_depth_distribution.py
python scripts/plot_lateral.py
```

CI does the same via `.github/workflows/sweep.yml` once `GATE_DATA_DIR` and
(optionally) `SSD_CACHE` are set as repo variables.

## Open questions and next steps

* **Pick a physically representative cloud radius.** 0.1 mm gives clean
  physics but underestimates literature charge-sharing widths. Probably
  `r = 0.15–0.20 mm` is the right production value, possibly combined with
  enabling a real diffusion model so the discrete staircasing doesn't return.
  Decision deferred.
* **Disk-shaped photoelectron cloud.** No built-in option in SSD; would need a
  custom `Event(locations, energies)` factory that samples a disk or oblate
  ellipsoid in a chosen direction. Back-burner per user request.
* **Real preamp calibration.** `C_FEEDBACK_PF = 1.0` is a placeholder — drop
  in the measured feedback capacitance of the real CSA to convert the volts
  axis to the actual mV/keV the hardware produces.
* **WP-cache portability.** Julia `Serialization` is version-specific
  (Julia + SolidStateDetectors). If either is upgraded on the cluster the
  cache will fail to load and the scripts will fall back to recomputing.
  Document the rebuild step in the runbook when that happens.
* **Charge diffusion model.** SSD has none configured in
  `czt_cross_strip_full.yaml`. Adding a thermal-diffusion / drift-broadening
  term would smooth single-point ideal rises further and is a more honest
  model of the real detector physics.
* **Test scripts removed from the staircase investigation.** The four
  negative-result tests (`test_cloud_steps`, `test_anode_refine`,
  `test_field_refine`, `test_pointcharge`) are not in git. The one positive
  result (`diagnostics/staircasing_radius_fix.jl`) is committed. The
  negative findings are recorded in the long-form memory note
  `project_wp_diagnostics.md` under `~/.claude/projects/.../memory/` — pull
  that into the repo if you want it on the cluster too.
